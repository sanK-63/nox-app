# Инференс и оптимизация LLM

LLM огромны — их нужно сжимать, ускорять и эффективно сервить.

## Квантование (Quantization)

Уменьшение точности весов: FP32 → FP16 → INT8 → INT4 → INT2.

| Тип | Бит | Размер 70B | Качество | Скорость |
|-----|-----|-----------|----------|----------|
| FP16 | 16 | ~140 GB | 100% | 1x |
| INT8 | 8 | ~70 GB | ~99.5% | ~1.1x |
| INT4 | 4 | ~35 GB | ~97-99% | ~1.3x |
| INT2 | 2 | ~18 GB | ~90-95% | ~1.5x |

### Методы квантования

| Метод | Как работает | Когда |
|-------|-------------|-------|
| **GPTQ** | Post-training, weight-only, layer-wise | GPU-инференс, продакшн |
| **GGUF** (llama.cpp) | Post-training, CPU-оптимизирован | CPU, Mac, Ollama |
| **AWQ** | Активация-аварное квантование | Лучше GPTQ на малых битностях |
| **Bitsandbytes** (4-bit) | Inference-ready, без калибровки | Hugging Face transformers |
| **FP8** (H100 native) | Аппаратное квантование | H100/B200 нативный |

## KV Cache

**Проблема:** При генерации каждый токен смотрит на все предыдущие. Вычисление attention заново на каждом шаге — O(n²).

**Решение:** Кэшируем Key (K) и Value (V) матрицы для всех предыдущих токенов.

```
Шаг 1: Q·[K1]·V1 → токен 1, KV cache = {token1}
Шаг 2: Q·[K1,K2]·[V1,V2] → токен 2, KV cache = {token1, token2}
...
```

**Размер KV cache:** 2 × n_layers × n_heads × d_head × context_length × 2 bytes
- 70B модель, 4K контекст → ~5 GB KV cache на один запрос
- 1M контекст → ~1.2 TB на запрос (нужны оптимизации)

### Оптимизации KV Cache

| Техника | Ускорение | Как |
|---------|-----------|-----|
| **GQA** (Grouped-Query Attention) | 2-4x меньше памяти | Группировка query heads |
| **MQA** (Multi-Query Attention) | 4-8x меньше | Все query heads делят K,V |
| **PagedAttention** (vLLM) | Почти 0 fragmentation | Кэш разбит на страницы как в ОС |
| **KV cache quantization** | 2x | Квантование кэша до INT8/INT4 |
| **Prefix caching** | Зависит от задачи | Переиспользование общего префикса |
| **Sliding Window** | O(window) вместо O(n) | Attention только на последние N токенов |

## Speculative Decoding

**Проблема:** Авторегрессивная генерация — один токен за раз (нельзя параллелить).

**Идея:** Маленькая "draft" модель генерирует K токенов. Большая модель проверяет их за 1 forward pass. Принимает совпавшие, корректирует первый несовпавший.

```
Draft (маленькая):  [A] [B] [C] [D] [E]
Target (большая):   [A] [B] [C] [X]       → D rejected, [A,B,C,X] accepted
                                                   ↑ 3 токена за 1 forward
```

**Ускорение:** 1.5x–3x (зависит от совпадения draft и target).

## Serving (продакшн-инференс)

| Система | Язык | Особенности |
|---------|------|-------------|
| **vLLM** | Python | PagedAttention, continuous batching, SOTA throughput |
| **llama.cpp** | C++ | CPU + GPU, GGUF, минимальные зависимости |
| **SGLang** | Python | Structured generation, радикальное ускорение для JSON/кода |
| **TGI** (HF) | Rust | Hugging Face stack, оптимизирован |
| **TensorRT-LLM** | C++ | NVIDIA, максимальная производительность на H100/B200 |
| **Ollama** | Go | Простота: `ollama run`, автоматическая загрузка моделей |

### Continuous Batching

```
Без batching:
[Запрос 1 ████████████████]
[Запрос 2                ████████████████]
[Запрос 3                             ████████████████]
С continuous batching:
[Запрос 1 ████]
[Запрос 2 ██████████]
[Запрос 3 ████████████████]
→ GPU всегда занята, throughput ×5-10
```

## Flash Attention

**Проблема:** Attention — узкое место (IO-bound, не compute-bound).

**Идея:** Делаем матричные операции прямо в SRAM (быстрая память чипа), не выгружая в HBM (медленная).

- Flash Attention 1 (2022): x2 ускорение
- Flash Attention 2 (2023): x2-3 от FA1
- Flash Attention 3 (2024): FP8 поддержка, H100 native
- Flash Attention 4 (2025): ещё +30% к FA3

**Итог:** FA делает длинные контексты (1M+) практичными.

### Команды для теста

```powershell
# Ollama с CUDA
winget install Ollama.Ollama

# Проверить что CUDA работает
ollama run --help  # флаг -ngl (num-gpu-layers)

# Запуск с полным оффлоудом
ollama run qwen2.5:1.5b --num-gpu-layers 999

# Запуск 7B с частичным оффлоудом
ollama run qwen2.5:7b --num-gpu-layers 24

# Замерить скорость
$measure = "Напиши короткое эссе про ИИ"
Measure-Command { $measure | ollama run qwen2.5:1.5b --num-gpu-layers 999 }
```

Отключить GPU оффлоуд: `$env:OLLAMA_GPU_OVERHEAD="0"` или `--num-gpu-layers 0`.
